### [cite_start]1. 개발 배경 및 중요성 [cite: 1]

#### 1.1. [cite_start]개발 배경 [cite: 2]
**1.1.1. [cite_start]주식 시장과 정보의 비대칭성** [cite: 2]
* 2025년 국내 상장사의 수는 약 2,700개로 매일 수만 건의 공시 자료와 뉴스 기사들이 쏟아지고 있다. [cite: 2]
* [cite_start]기관 투자자와 같은 대규모 자본과 정보를 갖춘 집단은 이러한 방대한 데이터들을 실시간으로 분석하고, 투자 전략을 세울 수 있다. [cite: 3]
* [cite_start]하지만 시간과 비용이 제한적인 개인 투자자들은 이러한 정보들 속에서 유의미한 관계를 파악하는 데 한계를 느낀다. [cite: 4]
* 이러한 정보의 비대칭성은 개인 투자자들을 리스크에 노출시키는 주요 원인이 된다. [cite: 5]

**1.1.2. [cite_start]기존 AI 모델의 한계** [cite: 6]
* 최근 대형 언어 모델(LLM)이 기업 데이터 분석에 도입되고 있으나, 일반적인 LLM은 데이터 간의 복잡한 인과관계를 정확히 계산하지 못하고 존재하지 않는 사실을 지어내는 환각 현상(Hallucination)이라는 치명적인 약점을 노출하고 있어 신뢰도 높은 금융/기업 분석에 활용하기 어렵다. [cite: 6]
* [cite_start]현대의 주식 시장과 산업 생태계는 기업 간의 인수합병(M&A), 순환출자, 임원 겸직 등으로 인해 그 관계망이 점점 복잡해지고 있다. [cite: 7]
* [cite_start]특히 IT, 게임, 엔터테인먼트 등 특정 산업군에서는 합작 법인 설립이나 지분 투자를 통한 연쇄적인 합종연횡이 빈번하게 발생하고 있다. [cite: 8]
* 그러나 LLM의 경우 이러한 데이터 간의 복잡한 인과관계를 정확히 짚어내지 못한다. [cite: 9]

#### 1.2. 필요성 및 중요성 [cite: 10]
**1.2.1. [cite_start]다중 연결 추론(Multi-hop Reasoning)의 필요성** [cite: 10]
* 기존 AI 모델의 한계를 해결하기 위해, 신뢰할 수 있는 외부 데이터를 먼저 검색하여 LLM에 제공하는 ‘검색 증강 생성(RAG, Retrieval-Augmented Generation)’ 기술이 필수적이다. [cite: 10]
* [cite_start]기존 RAG의 경우, 개별 텍스트의 유사성만 찾을 뿐 숨겨진 논리적 연결고리를 탐색하지 못하는 단점이 있었다. [cite: 11]
* [cite_start]우리 팀은 이 점을 해결하기 위해 지식 그래프 기반 RAG(Knowledge Graph-based RAG, 이하 ‘Graph RAG’)를 도입하였다. [cite: 12]
* Graph RAG는 주체, 관계, 객체로 이루어진 삼중항으로 관계 데이터를 표현한다. [cite: 13]
* [cite_start]이 데이터 노드는 엣지로 연결되며 논리적인 관계가 구조화된 지식 그래프를 이룬다. [cite: 14]
* [cite_start]기존 RAG는 단순 청크의 의미적 유사도로 관련 지식을 찾아오지만, Graph RAG는 의미적 유사도와 무관하게, 동일하거나 관련된 엔티티 및 관계를 포함하는 청크들을 연결하여 확장한다. [cite: 15]
* 이를 통해 검색된 청크들의 다양성을 확보하고 다중 연결 추론에 적합한 이점을 갖는다. [cite: 16]
* [cite_start]주식 시장에서 상장사 간의 복잡한 관계를 더 정확히 가져오기 위해서 Graph RAG를 사용하는 것이 중요하다. [cite: 17]

**1.2.2. [cite_start]직관적인 시각화를 통한 데이터 해석 및 의사결정 시간의 획기적 단축** [cite: 18]
* 주식 투자를 처음 시작하는 사람들에게 정보의 복잡성은 큰 걸림돌이 된다. [cite: 18]
* [cite_start]기업의 재무 정보, 산업 구조, 지분 관계, M&A 사례 등 다양한 데이터가 존재하지만, 대부분의 투자 플랫폼은 이러한 정보를 전문 투자자 기준으로 제공하거나 여러 화면으로 분산되어 있어 초보 투자자는 정보 탐색에 어려움을 겪는다. [cite: 19]
* [cite_start]이러한 문제를 해결하기 위해서는 보기 쉬운 인터페이스가 필요하다. [cite: 20] [cite_start]단순히 정보를 많이 제공하는 것보다는 이해하기 쉽게 정리되고 시각화된 정보를 제공하는 것이 중요하다. [cite: 20]
* [cite_start]이러한 친절한 디자인은 궁극적으로 더 많은 소비자에게 선택될 수 있는 중요한 요소가 된다. [cite: 21]

### [cite_start]2. 개발 목표 [cite: 21]

#### 2.1. [cite_start]시스템 구축 목표 [cite: 22]
* **2.1.1. [cite_start]실시간 데이터 파이프라인 구축**: DART Open API를 활용하여 상장사의 정형 데이터(지분 구조, 이사회 명단)를 100% 사전 구축하고, 질의 발생 시 네이버 뉴스 API로 비정형 데이터(최신 M&A, 분쟁 이슈)를 실시간으로 보완하여 수집하는 고효율 파이프라인 구현. [cite: 22]
* **2.1.2. [cite_start]다중 연결 추론을 위한 지식 그래프 DB 구축**: 특정 핵심 산업군(예: IT/게임)을 타겟으로 기업, 인물, 사건 간의 심층적인 인과관계를 노드(Node)와 엣지(Edge)로 구조화하여 Neo4j에 적재하고, 기존 LLM의 환각 현상을 원천 차단하는 Graph RAG 기반 핵심 추론 엔진 개발. [cite: 23]
* **2.1.3. [cite_start]직관적인 관계망 시각화 및 사용자 친화적 UI 제공**: 복잡한 텍스트나 표 대신, 질의 결과로 도출된 연관 기업들의 서브그래프(Subgraph)를 반응형 노드 맵(Node Map)으로 시각화하여 제공. [cite: 24] [cite_start]이를 통해 국내 주식 시장의 주요 참여층인 중장년층을 포함한 일반 투자자들도 직관적으로 데이터를 해석할 수 있는 접근성 높은 인터페이스 구축. [cite: 25]

#### 2.2. [cite_start]기술적 개발 목표 [cite: 26]
* **2.2.1. [cite_start]비정형 데이터의 정제 및 지식 구조화 기술 개발**: 자연어 처리(NLP) 및 LLM 정보 추출 기법을 활용하여, 매일 쏟아지는 방대한 비정형 텍스트(뉴스, 공시 등) 속에서 핵심 엔티티(기업, 인물)와 그들 간의 관계(인수, 겸직 등)를 정확히 선별하고, 이를 지식 그래프(Knowledge Graph)가 인식할 수 있는 JSON 스키마 형태로 자동 변환 및 적재하는 파이프라인 구축. [cite: 26]
* **2.2.2. [cite_start]Hallucination 최소화 및 신뢰성 극대화**: 기존 LLM의 치명적 한계인 Hallucination 현상을 최소화하기 위해, 문맥과 의미를 이해하는 벡터 검색(Vector DB)과 명확한 팩트 및 다중 연결 논리를 추적하는 그래프 검색(Graph DB)의 장점만을 결합한 하이브리드 Graph RAG 아키텍처 설계 및 도입. [cite: 27]
* **2.2.3. [cite_start]LLM 기반 지능형 질의 분석 및 동적 탐색 엔진 구현**: 사용자가 자연어 질의(Query)가 입력되었을 때, 단순 키워드 매칭에 그치지 않고 LLM이 스스로 질의의 의도와 필요한 탐색 뎁스(Depth)를 분석함. [cite: 28] [cite_start]이를 바탕으로 최적의 그래프 탐색 쿼리(예: Cypher)를 자율적으로 생성하여 DB를 탐색하고, 추출된 팩트 데이터만을 조립하여 최종 답변을 합성하는 지능형 추론 엔진 개발. [cite: 29]

### [cite_start]3. 차별성 [cite: 30]
* 현재 국내에서 기업 정보 및 공시 데이터를 제공하는 다양한 서비스가 존재한다. [cite: 30] 대표적인 예로 금융감독원의 DART 시스템, 기업 정보 분석 서비스인 FnGuide, 그리고 NICE Information Service 등이 있다. [cite: 31]
* [cite_start]그러나 이러한 서비스들은 주로 공시 정보 조회나 재무 정보 제공에 초점을 맞추고 있다. [cite: 32] [cite_start]따라서 기업 간 관계를 통합적으로 분석하거나 자동화된 분석 결과를 제공하는 기능은 제한적이다. [cite: 33]
* DART 시스템은 상장기업의 공시 정보를 가장 공식적으로 제공하는 플랫폼이지만, 사용자는 특정 기업의 공시 문서를 직접 검색하고 내용을 확인해야 한다. [cite: 34] 즉, 기업 간 지분 관계나 투자 관계를 자동으로 분석하여 시각적으로 제공하지는 않는다. [cite: 35] 또한 공시 문서가 주로 텍스트 형태로 제공되기 때문에 여러 기업 간 관계를 파악하기 위해 사용자가 직접 정보를 해석해야 하는 불편함이 있다. [cite: 36]
* [cite_start]FnGuide나 NICE평가정보와 같은 금융 정보 서비스는 기업의 재무 데이터를 제공하지만, 기업 간 관계 분석 기능은 제한적으로 제공되거나 전문 기관을 위한 유료 서비스인 경우가 많다. [cite: 37] [cite_start]기업 간 지배 구조를 그래프 형태로 제공하거나 공시 기반의 M&A 사례를 분석하는 기능은 일반 사용자에게 쉽게 접근 가능한 형태로 제공되지 않는다. [cite: 38]
* **본 프로젝트의 차별성**:
    1. 공시 데이터와 최신 뉴스 데이터를 자동 수집하고 구조화하여 분석에 활용한다. [cite: 40]
    2. 기업 간 관계를 지식 그래프 RAG 기반으로 분석하여 정확도 높은 수준의 답변을 제공한다. [cite: 41]
    3. 사용자 접근성을 높이고 정보 사용에 익숙지 못한 투자자들에게 사용 편의성을 제공한다. [cite: 42]

### 4. 개발 방법 및 체계 [cite: 44]
본 프로젝트는 애자일 방법론을 채택하여 서브 모듈별로 동시 개발을 진행한다. [cite: 44]

* **4.1. [cite_start]모듈 A - 진형규 (하이브리드 데이터 파이프라인)** [cite: 45]
    * [cite_start]**역할**: 상장사 정형 데이터 및 뉴스 비정형 데이터의 수집 및 노이즈 정제. [cite: 45]
    * [cite_start]**구현**: DART Open API 및 네이버 뉴스 API 크롤링, 정규표현식 기반 전처리 수행. [cite: 46, 47]
* **4.2. [cite_start]모듈 B – 김요한 (지식 구조화 및 하이브리드 DB 적재)** [cite: 47]
    * **역할**: 금융 도메인 특화 온톨로지 기준 지식 추출 및 벡터/그래프 DB 최적화 적재. [cite: 47]
    * [cite_start]**구현**: Chroma(벡터 DB)를 통한 임베딩 문서 검색, Neo4j(그래프 DB)를 통한 엔티티 및 관계 구조화 저장. [cite: 48, 49]
* **4.3. [cite_start]모듈 C – 문예랑 (지능형 RAG 엔진 및 API 백엔드)** [cite: 50]
    * **역할**: 사용자 질의 자율 분석 및 통합 DB 탐색을 통한 답변 생성. [cite: 50]
    * [cite_start]**구현**: FastAPI 기반 REST API 서버 구축, LangChain ReAct 프레임워크 및 LangGraph 도입으로 안정성 확보. [cite: 51, 52]
* **4.4. [cite_start]모듈 D - 마혜민 (대화형 UI 및 노드 시각화 프론트엔드)** [cite: 53]
    * **역할**: 사용자 상호작용 및 분석 결과(텍스트, 그래프 시각화) 제공. [cite: 53]
    * [cite_start]**구현**: Streamlit 기반 인터페이스 구축, RAG 토글 배치, PyVis를 이용한 기업 관계망 시각화. [cite: 54, 55, 56]

### [cite_start]5. 개발 추진 계획 [cite: 57]
[cite_start]총 12주 간의 개발 일정을 따름. [cite: 57]
1. 요구사항 분석 및 시스템 아키텍처/DB 스키마 설계 (1주)
2. DART 및 뉴스 API 연동, 데이터 크롤러 개발 (2주)
3. 원시 텍스트 노이즈 정제 및 전처리 (2주)
4. 개체명 인식(NER) 및 관계 추출용 LLM 프롬프트 설계 (2주)
5. 하이브리드 DB 적재 및 지식 구조화 (4주)
6. LangGraph 기반 지능형 추론 엔진 설계 (4주)
7. FastAPI 서버 구축 및 Cypher API 구현 (1주)
8. Figma UI/UX 기획 및 Streamlit 웹 인터페이스 구현 (5주)
9. PyVis 등 시각화 라이브러리 연동 및 노드 맵 렌더링 (4주)
10. 모듈 간 시스템 연동 및 베타 테스트 (3주)
11. 성능 비교, 디버깅 및 문서화 (1주)

### [cite_start]6. 기대 효과 [cite: 58]
* **6.1. [cite_start]반응형 시각화를 통한 투자 정보 접근성 향상**: 파편화된 공시와 이슈를 통합하여 반응형 노드 맵으로 제공함으로써 초보 투자자와 중장년층의 정보 접근성을 극대화함. [cite: 58, 59]
* **6.2. [cite_start]다중 연결 추론 기반의 투자 의사결정 지원 강화**: 지배 구조, 임원 겸직 등 다차원 관계 지표를 통해 심층적인 산업 생태계 분석과 합리적인 투자 의사결정을 지원함. [cite: 60, 61]
