# RAG ON/OFF 평가 루브릭

## 평가 목적

이 루브릭은 프로젝트의 기업 공시, 뉴스, 그래프 기반 질의응답 태스크에서 RAG 적용이 답변 품질을 개선하는지 평가하기 위한 기준이다.

비교 대상은 다음과 같다.

- RAG OFF: 프로젝트 DB 검색 없이 LLM만 사용한 답변
- RAG ON: Chroma, Neo4j, DART 데이터, 뉴스 데이터, graph output 등 프로젝트 근거를 검색해 사용한 답변

이 평가는 일반적인 LLM 성능 전체를 비교하는 것이 아니다. 기업 공시, 뉴스, 지분 구조, entity-relation graph에 기반한 도메인 특화 질의응답 성능을 비교한다.

RAG OFF와 RAG ON 모두 동일한 `rag_eval_questions.jsonl` 질문 세트를 사용한다. 채점 기준 자료는 각 문항의 `answer`, `expected_reasoning`, `evidence_hint`, `answer_type`이다. 자동 채점에는 원본 필드를 유지하면서 채점 메타데이터를 추가한 `rag_eval_questions_enriched.jsonl`을 사용한다.

## 점수 개요

각 답변은 4개 평가 항목으로 채점한다. 각 항목은 1점부터 5점까지의 정수 점수를 부여한다.

| 평가 항목 | 가중치 |
| --- | ---: |
| 사실 정확도 | 40% |
| 관계 추론 정확도 | 25% |
| 근거 활용도 | 20% |
| 환각 억제력 | 15% |

1~5점 기준 가중 평균 계산식:

```text
weighted_score_1_to_5 =
fact_accuracy * 0.40 +
relation_reasoning * 0.25 +
evidence_use * 0.20 +
hallucination_control * 0.15
```

100점 기준 환산식:

```text
weighted_score_100 =
(fact_accuracy / 5 * 40) +
(relation_reasoning / 5 * 25) +
(evidence_use / 5 * 20) +
(hallucination_control / 5 * 15)
```

## 1. 사실 정확도

사실 정확도는 답변이 기준 정답의 핵심 fact와 얼마나 일치하는지 평가한다.

핵심 fact에는 기업명, 지분율, 최대주주 여부, 관계 방향, 사건명, 인물명, 직책 등 질문 답변에 필요한 구체적 사실이 포함된다.

| 점수 | 기준 |
| ---: | --- |
| 5점 | 핵심 fact의 90~100%가 기준 정답과 일치한다. |
| 4점 | 핵심 fact의 70~89%가 기준 정답과 일치한다. |
| 3점 | 핵심 fact의 50~69%가 기준 정답과 일치한다. |
| 2점 | 핵심 fact의 20~49%가 기준 정답과 일치한다. |
| 1점 | 핵심 fact의 0~19%만 일치하거나, 답변이 대부분 틀렸다. |

## 2. 관계 추론 정확도

관계 추론 정확도는 답변이 직접 관계, 간접 관계, multi-hop 경로, 중간 기업, 관계 방향, 관계 유형을 얼마나 정확히 설명했는지 평가한다.

예를 들어 다음 경로가 정답인 경우:

```text
LG -> LG화학 -> LG에너지솔루션
```

채점 요소는 다음과 같다.

- 시작 기업
- 중간 기업
- 도착 기업
- 관계 방향
- 관계 유형: 최대주주, 지분 보유, 계열 관계, 투자 관계, 영향 후보 등

| 점수 | 기준 |
| ---: | --- |
| 5점 | 필요한 관계 요소의 90~100%가 기준 추론과 일치한다. |
| 4점 | 필요한 관계 요소의 70~89%가 기준 추론과 일치한다. |
| 3점 | 필요한 관계 요소의 50~69%가 기준 추론과 일치한다. |
| 2점 | 필요한 관계 요소의 20~49%가 기준 추론과 일치한다. |
| 1점 | 필요한 관계 요소의 0~19%만 일치하거나, 관계 추론이 거의 없다. |

## 3. 근거 활용도

근거 활용도는 답변의 핵심 주장이 검증 가능한 프로젝트 근거와 얼마나 잘 연결되는지 평가한다. URL 포함 여부만으로 평가하지 않는다. URL은 좋은 근거 신호지만, 정확한 문서명, 공시 유형, 출처 설명, 그래프 근거도 인정한다.

인정 가능한 근거는 다음과 같다.

- URL
- 문서명
- DART 공시명
- 뉴스 출처
- 그래프 DB 또는 관계 그래프 근거
- "DART 최대주주 현황 기준", "수집된 뉴스 기준"과 같은 근거 표현
- `evidence_hint`와 일치하거나 의미상 같은 근거

아래 4개 체크 요소로 채점한다.

1. 근거 출처 유형 명시: DART, 공시, 뉴스, 수집 데이터, 그래프, 지배구조 등 검증 가능한 출처 유형을 언급했는가
2. 근거 대상 명시: 어떤 기업, 문서, 공시, 기사, 그래프 관계를 근거로 삼았는지 알 수 있는가
3. 핵심 주장 연결: 답변의 핵심 fact나 관계가 근거와 연결되어 설명되는가
4. 필수 근거 범위 충족: 문항이 요구하는 source type을 충족했는가. 예를 들어 DART+뉴스 문항이면 둘 다 반영해야 한다.

| 점수 | 기준 |
| ---: | --- |
| 5점 | 4개 체크 요소를 모두 충족한다. |
| 4점 | 3개 체크 요소를 충족한다. |
| 3점 | 2개 체크 요소를 충족한다. |
| 2점 | 1개 체크 요소를 충족한다. |
| 1점 | 0개 체크 요소를 충족하거나, 근거가 없다. |

## 4. 환각 억제력

환각 억제력은 답변이 근거 없는 추가 정보를 얼마나 억제했는지 평가한다.

근거 없는 추가 정보에는 기준 정답, expected reasoning, evidence hint, 검색 근거에 없는 기업명, 지분율, 관계 유형, 사건, 뉴스, 인물, 직책 등이 포함된다.

점수가 높을수록 근거 없는 추가 정보가 적다.

| 점수 | 기준 |
| ---: | --- |
| 5점 | 근거 없는 추가 정보가 0개다. |
| 4점 | 근거 없는 추가 정보가 1개다. |
| 3점 | 근거 없는 추가 정보가 2개다. |
| 2점 | 근거 없는 추가 정보가 3~4개다. |
| 1점 | 근거 없는 추가 정보가 5개 이상이거나, 답변의 핵심이 근거 없는 주장으로 구성되어 있다. |

## LLM Judge 출력 형식

LLM을 평가자로 사용할 경우, 각 답변에 대해 아래 JSON 형식으로 한 개의 평가 결과를 출력한다.

```json
{
  "question_id": "chain_005",
  "system_type": "rag_on",
  "scores": {
    "fact_accuracy": 5,
    "relation_reasoning": 5,
    "evidence_use": 4,
    "hallucination_control": 5
  },
  "weighted_score_1_to_5": 4.8,
  "weighted_score_100": 96.0,
  "matched_facts": ["LG", "LG화학", "LG에너지솔루션", "최대주주"],
  "missing_facts": [],
  "hallucinated_claims": [],
  "brief_reason": "정답 경로와 관계 방향을 정확히 설명했고 DART 최대주주 현황을 근거로 언급했다."
}
```

## 평가 절차

1. `rag_eval_questions.jsonl`의 각 질문에 대해 RAG OFF 답변과 RAG ON 답변을 각각 생성한다.
2. 두 답변을 동일한 루브릭으로 채점한다.
3. `rag_eval_questions_enriched.jsonl`을 채점 메타데이터로 사용한다. 이 파일의 원본 `answer`, `expected_reasoning`, `evidence_hint`, `answer_type` 필드를 기준 자료로 사용한다.
4. 4개 평가 항목의 원점수와 가중 점수를 기록한다.
5. RAG OFF와 RAG ON의 평균 가중 점수, 항목별 평균 점수를 비교한다.
6. `direct_relation`, `multi_hop_chain`, `impact_inference` 유형에서 각각 최소 1개 이상의 대표 사례를 보고한다.

## 권장 검증 방식

전체 평가 전에 소규모 샘플을 먼저 수동 검토한다.

- `direct_relation` 질문 1개
- `multi_hop_chain` 질문 1개
- `impact_inference` 질문 1개

두 명 이상의 사람이 같은 답변을 채점할 경우, 항목별 점수 차이가 1점 이내인지 확인한다. 차이가 더 크면 해당 문항의 expected facts, relation elements, unsupported claims를 더 명확히 정의한 뒤 다시 채점한다.

## 전제 조건

- 이 평가는 RAG ON/OFF 비교를 위한 것이며, 일반 목적 LLM 벤치마크가 아니다.
- URL 포함 여부는 필수 조건이 아니다. URL은 근거 활용도를 판단하는 여러 신호 중 하나다.
- 이 프로젝트의 질문 세트는 DB-grounded 성격을 가진다. 이는 시스템의 목적이 기업 공시, 뉴스, 그래프 기반 질의응답이기 때문이다.
- `rag_eval_questions.jsonl`을 벤치마크 질문과 기준 정답의 출처로 사용한다.
- `rag_eval_questions_enriched.jsonl`은 LLM Judge 또는 채점 스크립트가 사용할 파생 평가 메타데이터 파일이다.
