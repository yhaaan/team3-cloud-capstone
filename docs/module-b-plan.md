# Module B 계획서

## 1. 모듈 개요
Module B는 Module A에서 전달받은 전처리된 비정형 텍스트를 하이브리드 데이터베이스에 저장할 수 있는 구조화된 지식으로 변환하는 역할을 담당한다.

이 모듈의 주요 출력은 두 가지이다.
1. Chroma에 저장할 벡터 검색용 텍스트 청크
2. Neo4j에 저장할 엔티티-관계 그래프 데이터

## 2. 입력
Module B는 Module A로부터 전처리된 금융 및 산업 관련 텍스트 데이터를 입력받는다.

예상 입력 필드:
- source_id: 문서 고유 ID
- title: 문서 제목
- content: 전처리된 본문 텍스트
- source: 출처 플랫폼 또는 제공자
- published_at: 발행일
- url: 원문 링크

예시 입력:

```json
{
  "source_id": "news_001",
  "title": "카카오, A사 인수 발표",
  "content": "카카오는 2026년 3월 20일 A사 인수를 발표했다. 이번 인수는 AI 사업 강화를 위한 전략적 결정이다.",
  "source": "naver_news",
  "published_at": "2026-03-20",
  "url": "https://example.com/news/001"
}
```

## 3. 출력
Module B는 두 가지 형태의 결과를 생성한다.

### 3-1. Chroma 출력
- 청크 단위로 분리된 텍스트
- 검색에 필요한 메타데이터
- 임베딩 대상 텍스트

### 3-2. Neo4j 출력
- 추출된 엔티티
- 추출된 관계
- 각 관계에 대한 근거 문장

## 4. 핵심 역할
- Module A에서 전처리된 텍스트를 입력받는다
- 텍스트를 청크 단위로 분할한다
- Chroma 저장용 메타데이터를 구성한다
- 온톨로지 기준으로 엔티티와 관계를 추출한다
- 추출 결과를 그래프 JSON 형식으로 변환한다
- 청크 데이터를 Chroma에 저장한다
- 엔티티-관계 데이터를 Neo4j에 저장한다

## 5. 버전 1 범위
버전 1은 최소 동작 파이프라인 구현을 목표로 한다.

v1 포함 범위:
- 단일 문서 입력 처리
- 단순 청크 분할
- 온톨로지 기반 엔티티 추출
- 온톨로지 기반 관계 추출
- JSON 출력 생성
- Chroma 저장
- Neo4j 저장

v1 제외 범위:
- 고급 문서 중복 제거
- 신뢰도 점수 보정
- 여러 별칭에 대한 엔티티 연결
- 운영 수준의 예외 처리
- 배치 스케줄링 파이프라인

## 6. 의존성
- Python
- ChromaDB
- Neo4j
- LLM API 또는 로컬 LLM
- Sentence Transformers

## 7. 협업 지점

### Module A
Module A는 메타데이터가 포함된 정제 텍스트를 제공해야 한다.

### Module C
Module C는 Module B가 생성한 Chroma/Neo4j 데이터를 조회하여 질의응답에 활용한다.

## 8. 개발 단계
1. 온톨로지 확정
2. 청크 스키마 확정
3. 그래프 스키마 확정
4. 청킹 파이프라인 구현
5. 임베딩용 청크 출력 구현
6. 엔티티-관계 추출 프롬프트 작성
7. 그래프 JSON 파서 구현
8. Chroma 적재기 구현
9. Neo4j 적재기 구현
10. 샘플 문서 테스트

## 9. 성공 기준
다음 조건을 만족하면 Module B가 최소 성공한 것으로 본다.
- 입력 문서 1개를 청크로 분할하여 Chroma에 저장할 수 있다
- 같은 문서에서 엔티티와 관계를 추출할 수 있다
- 추출된 그래프 데이터를 Neo4j에 저장할 수 있다
- 이후 Module C가 두 출력을 사용할 수 있다
